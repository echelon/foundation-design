## 1. Two concepts, two tables (DECIDED 2026-07-14)

**Sign-off:** _unsigned_

Yes — two tables. The design splits **storage** from **provenance**
(`../reports/read/files-naming.md`):

| Table     | Role                                                                        |
| --------- | ---------------------------------------------------------------------------- |
| `files`   | The storage primitive: bytes in R2 with mime, size, checksum, CDN URL. A file doesn't know or care what it *means*. Uploads AND generated bytes alike |
| `outputs` | The job-product record: "job X produced this, at index 2, of kind video." Pure provenance — it **references** a `files` row rather than carrying its own storage columns |

- **Renamed `job_outputs` → `outputs`** (bt, 2026-07-14: too much to type). The `out_` prefix
  is unchanged. The `job_id` FK already says whose output it is.
- Jobs have **zero or more** outputs (a failed job has none; a batch image job has several).
- Everything durable is ultimately a file: an input photo, a generated video, a thumbnail —
  someday LoRA weights, a fine-tune checkpoint, an exported embeddings blob.
- **Remix seam:** any `file_...` ID is valid in any input slot — the output of job A is an
  input of job B with no conversion. This is the workflow foundation.
- **Fine-tunes seam:** a future trained thing (LoRA, fine-tune, full model) is its own
  resource (`custom_models`-style) whose *weights* are files. The resource carries semantics
  (base model, training config, status); the file carries bytes. Never "special files."
- **Text is an output too:** LLM/text products are outputs of `kind = text`, stored inline
  on the output row when small, spilled to a real file when large.

## 2. Tables

**Sign-off:** _unsigned_

### files  (`file_`) — the storage primitive

| column           | type        | null? | notes                                                                            |
| ---------------- | ----------- | ----- | -------------------------------------------------------------------------------- |
| sequence_id      | bigint      | no    | identity; never exposed (ids.md §4)                                              |
| id               | text PK     | no    | `file_...`                                                                       |
| account_id       | text FK     | no    | → accounts                                                                       |
| purpose          | text        | no    | `input \| output \| avatar \| …`                                                 |
| origin           | text        | no    | `upload \| mirrored_url \| generated`                                            |
| origin_url       | text        | yes   | source URL when mirrored; the provider's expiring URL when generated (debugging) |
| storage_key      | text        | no    | R2 object key                                                                    |
| cdn_url          | text        | no    | durable, ours                                                                    |
| mime             | text        | no    |                                                                                  |
| bytes            | bigint      | no    |                                                                                  |
| checksum_sha256  | text        | no    |                                                                                  |
| storage_class    | text        | no    | `hot \| cold` — forever-retention with cold migration (architecture.md §8)       |
| created_at       | timestamptz | no    |                                                                                  |

Generated bytes get `purpose = output`, `origin = generated`, `origin_url` = the upstream URL
we ingested from. The long-term hosting product is ACLs + serving tiers **on files** — no new
primitive needed.

### outputs  (`out_`) — job products, pure provenance

| column        | type        | null? | notes                                                                                   |
| ------------- | ----------- | ----- | --------------------------------------------------------------------------------------- |
| sequence_id   | bigint      | no    | identity; never exposed (ids.md §4)                                                     |
| id            | text PK     | no    | `out_...`                                                                               |
| job_id        | text FK     | no    | → jobs                                                                                  |
| file_id       | text FK     | yes   | → files; null ONLY for inline-text outputs                                              |
| output_index  | int         | no    | 0-based within the job                                                                  |
| kind          | text        | no    | `image \| video \| audio \| mesh \| splat \| thumbnail \| text` (`enums.md` OutputKind) |
| width         | int         | yes   |                                                                                         |
| height        | int         | yes   |                                                                                         |
| duration_ms   | int         | yes   |                                                                                         |
| text_content  | text        | yes   | inline text product when small; large text spills to a file                             |
| created_at    | timestamptz | no    |                                                                                         |
|               |             |       | CHECK (file_id IS NOT NULL OR text_content IS NOT NULL)                                 |
|               |             |       | UNIQUE (job_id, output_index)                                                           |

Storage details (key, CDN URL, mime, bytes, checksum, class, provider URL) moved to `files`
— the report's refinement, adopted: "outputs become pure provenance + FK; unifies storage
handling before the hosting/remix products land. Cheap now, annoying later."

## 3. API surface

**Sign-off:** _unsigned_

- `POST /v1/files` — multipart upload → `file_...` usable in any input slot (`api.md` §7).
- Outputs are **embedded** in job responses (`GET /v1/jobs/{id}` returns the outputs array
  with CDN URLs); no standalone `/v1/outputs` listing in v1.
- `succeeded` is set only AFTER outputs' bytes are ingested into our storage (`jobs.md` §2)
  — a `succeeded` job's output URLs are always durable, ours.
